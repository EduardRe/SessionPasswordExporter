# Session Password Exporter

[English version](README.en.md)

Приложение на Rust для Windows 10/11 с графическим интерфейсом и CLI. GUI построен на **egui + eframe**. CLI и GUI используют одно ядро для загрузки, разбора и экспорта данных.

Это независимое приложение, не связанное с WinSCP или его разработчиками. Название WinSCP используется только для обозначения поддерживаемых конфигураций.

## Структура проекта

```text
src/
├── main.rs              # запуск приложения
├── lib.rs               # общая библиотека и публичные модули
├── cli.rs               # аргументы CLI и выбор режима GUI/CLI
├── core/                # логика WinSCP и общие модели
│   ├── crypto.rs        # форматы паролей и криптография WinSCP
│   ├── export.rs        # текстовый, JSON- и XML-экспорт
│   ├── grouping.rs      # группировка сессий по файлам-источникам
│   ├── input.rs         # загрузка файлов и обход каталогов
│   ├── master_password.rs # разблокировка защищённых конфигов
│   ├── model.rs         # сессии, пароли, форматы и настройки
│   ├── parser.rs        # разбор INI и дерево папок WinSCP
│   ├── recovery.rs      # перебор мастер-пароля и зашифрованный checkpoint
│   └── registry.rs      # чтение конфигурации из реестра Windows
├── config/              # константы, локализация и сохранение настроек
└── ui/                  # окно egui и отображение дерева сессий
    └── session_tree.rs  # построение и отрисовка папок и сессий
```

Тесты находятся рядом с модулями, которые проверяют (`#[cfg(test)]`). Так GUI, CLI, парсер и экспорт используют общую реализацию без копирования логики.

## Сборка и запуск

Из корня репозитория:

```powershell
cargo run                         # графический режим
cargo run -- --help               # справка CLI
cargo run -- "C:\backup\WinSCP.ini" --format json --output sessions.json
cargo run -- "C:\backup\configs" --format text
cargo run -- --registry --format xml --output sessions.xml
cargo test                        # модульные тесты
cargo fmt --check                 # проверка форматирования
cargo build --release             # оптимизированная сборка
.\scripts\build-windows-packages.ps1 # автоматически подготовит инструменты и соберёт пакеты в dist\
```

Скрипт сам добавит недостающие цели Rust для x86/x64 и при необходимости скачает официальный установщик Inno Setup 7, проверит его цифровую подпись и установит компилятор для текущего пользователя. Для этого нужен интернет. Скрипт создаёт приложения x86/x64, соответствующие установщики, Portable ZIP с обеими сборками и SHA-256 суммы в `dist/`. Windows-сборки статически связывают MSVC Runtime, поэтому отдельно устанавливать Visual C++ Redistributable не требуется. Скрипт использует версию из `Cargo.toml`; менять её для локальной сборки не нужно.

При ошибке запуска GUI приложение показывает окно с причиной и путём к `startup.log`. Лог создаётся рядом с EXE, а если папка защищена от записи (например, `Program Files`) — в `%LOCALAPPDATA%\SessionPasswordExporter\startup.log`. Содержимое сессий и пароли в лог не записываются.

На Windows для графического интерфейса используется Direct3D 12. Vulkan-драйверы не требуются.

CLI принимает один или несколько файлов и каталоги с INI. В GUI конфиги можно выбрать, перетащить в окно отдельными файлами или директориями (папками), либо прочитать из реестра. Приложение рекурсивно ищет INI-файлы во вложенных папках. Сессии сгруппированы по источникам; заголовок файла показывается без расширения, группы и вложенные папки WinSCP можно сворачивать и разворачивать. Поиск в реальном времени работает по названию, хосту и пользователю; в настройках можно включить исключение свернутых групп из поиска. Кнопка «Очистить список» удаляет загруженные подключения из текущего списка. Экспорт в текст, JSON и XML также сохраняет группы источников. Пароли скрыты по умолчанию; в настройках можно выбрать действие кнопки пароля, язык **Русский** или **English**, а также тему **Системная**, **Светлая** или **Тёмная**. Язык и тема по умолчанию определяются системой.

Повторная загрузка файла, папки или реестра заменяет уже загруженные подключения из того же источника и не создаёт дубликаты. Кнопка `×` в поле поиска очищает запрос.

## GitHub Actions и релизы

Каждый push и pull request запускает на Windows форматирование, Clippy, тесты и сборку пакетов тем же скриптом, который можно запустить локально. Каждый успешный push в `master` также публикует релиз с тегом `master-<commit>`, содержащий установщики x86/x64, Portable ZIP и SHA-256 суммы. Номер версии из `Cargo.toml` указывается в названии релиза и не меняется автоматически. GitHub автоматически прикладывает к релизу архивы исходного кода. Стабильный релиз с тегом `v<версия>` публикуется отдельно при отправке соответствующего тега; перед его выпуском версию в `Cargo.toml` нужно изменить вручную.

Установщик работает в профиле текущего пользователя без прав администратора; на шаге установки можно выбрать ярлыки в меню «Пуск» и на рабочем столе. В Portable ZIP сборки расположены в папках `x86/` и `x64/`. Файл `portable.mode` в корне включает общее хранилище настроек `data/settings.json` для обеих версий. При первом запуске существующие настройки пользователя копируются туда, если локального файла ещё нет.

## Ограничения и безопасность

Если загружен конфиг с паролями WinSCP, защищёнными мастер-паролем, доступны ввод мастер-пароля и его подбор отдельно для выбранного конфига или для всех загруженных защищённых конфигов. Поддерживаются три режима шифрования WinSCP, включая старые конфиги. Пароль проверяется для каждого источника отдельно: в разных файлах мастер-пароли могут различаться.

Подбор выполняется в фоновом потоке. Можно включить цифры, буквы и спецсимволы (включая пробел) и задать длину комбинации от 1 до 100 000 символов. Интерфейс показывает текущую комбинацию, число проверок, её длину, скорость и затраченное время. Большие диапазоны могут требовать очень долгого времени: верхний предел длины не означает, что полный перебор практически выполним.

Прогресс подбора и найденные им мастер-пароли сохраняются в `recovery-state.dat` перед запуском, каждые 5 секунд, а также при паузе, остановке и завершении. Файл шифруется Windows DPAPI для текущей учётной записи Windows. В обычной установке он находится рядом с настройками в `%APPDATA%\Session Password Exporter\session-password-exporter\config\`; в Portable-версии — в `data/recovery-state.dat`. Чтобы сбросить прогресс и сохранённые результаты, закройте приложение и удалите этот файл. При повторном импорте неизменённого конфига с теми же параметрами поиск продолжается; изменение конфига сбрасывает старый результат, даже если путь не изменился.

Пароли, введённые вручную, хранятся только в памяти до закрытия приложения. Найденные при подборе пароли сохраняются только в зашифрованном checkpoint, а не в настройках. При копировании или экспорте закрытые конфиги можно пропустить; перед действием приложение показывает, какие источники войдут в результат.

Не помещайте конфиги с паролями в репозиторий. Экспорт и буфер обмена содержат пароли открытым текстом и выполняются по явному действию пользователя. Релизы, установщик и Portable ZIP содержат файл [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) с уведомлением о стороннем компоненте.
